# WLED YaHA

Несколько гирлянд WLED в «Доме с Алисой» через [YaHA](https://github.com/dext0r/yandex_smart_home). Выбор устройств, сопоставление сцен и профили настраиваются на одной странице Home Assistant.

Управление выполняет штатная интеграция [WLED](https://www.home-assistant.io/integrations/wled/): питание, яркость, поддерживаемые цвета и пресеты. Подходит в том числе для Gledopto GL-MC-001WL с WLED. Отдельный MQTT или blueprint не требуется.

## Установка и обновление

[Добавить репозиторий WLED YaHA в HACS](https://my.home-assistant.io/redirect/hacs_repository/?owner=Odysseos&repository=ha_wled_yaha&category=integration).

Вручную в HACS: **⋮ → Пользовательские репозитории →** `https://github.com/Odysseos/ha_wled_yaha` → тип **Интеграция**. Скачай WLED YaHA и перезапусти Home Assistant.

1. Добавь гирлянды через **Настройки → Устройства и службы → Добавить интеграцию → WLED**, если они ещё не добавлены.
2. Добавь интеграцию **WLED YaHA** в том же разделе. При первоначальном добавлении создаётся редактор; экспорт ещё не изменяется.
3. Открой **WLED YaHA** в боковом меню HA. Доступ к редактору есть у администраторов.
4. Отметь нужные светильники слева. Для обычной гирлянды с одним сегментом выбирай цветной свет; общий свет многосегментного контроллера управляет питанием и общей яркостью.
5. Справа при желании сопоставь сцены Алисы и пресеты. Все сцены необязательны. Гирлянду без пресетов или временно недоступную гирлянду тоже можно включить в YaHA.
6. Проверь **Параметры экспорта** и нажми общее **Подтвердить**. При включённом автоэкспорте файл обновится через несколько секунд.
7. В параметрах YaHA выбери **YAML** как источник списка устройств, затем обнови устройства подключения YaHA в приложении **Дом с Алисой**.

При обновлении с **0.1.x** выбранные гирлянды и назначения сохраняются автоматически. Последовательные окна настройки заменены общей страницей. Если после обновления виден старый интерфейс, обнови страницу HA с очисткой кеша браузера.

Секция `wled_yaha:` в `configuration.yaml` не нужна. При установке через HACS копировать файлы вручную не требуется. Старый предварительный YAML-экспортёр, если он устанавливался отдельно до полной интеграции, следует отключить; его настройки автоматически не импортируются.

## Общий редактор

Интерфейс продолжает оформление **Entity ID Manager**: цвета текущей темы HA, кнопки и поля той же формы, фильтры над списком, нейтральные сохранённые значения и красные/зелёные метки изменений.

- **Слева — все WLED-светильники.** Естественная сортировка по имени: WLED2 перед WLED10; затем комната и entity ID. Рядом состояние: включена, выключена, недоступна, неизвестно или ещё не загружена. Статусы обновляются при изменениях HA. Доступность не меняет порядок списка.
- **Пресеты видны сразу.** Показано их количество, «Нет пресетов» для известного пустого каталога или «Пресеты не загружены», когда каталог неизвестен. Сохранённые назначения доступны и при временной недоступности устройства. Для них показывается пометка о последнем известном каталоге.
- **Справа — выбранная гирлянда и её сцены.** Переходить можно в любом порядке. Поиск работает по имени, комнате и entity ID; фильтры показывают выбранные, недоступные, без пресетов или изменённые гирлянды. На узком экране список располагается над назначениями.
- **Один общий черновик.** Переключение строк не сохраняет и не теряет правки. «Подтвердить» сохраняет все гирлянды, профили и параметры одной операцией. «Отмена» отменяет весь черновик, «Сбросить изменения» — только выбранную гирлянду. Снятие отметки YaHA сохраняет её назначения для повторного включения.
- **Защита от другого окна.** Если сохранённые настройки изменились параллельно, редактор оставляет черновик открытым и блокирует его перезапись. «Отмена» загружает актуальную версию.

Просмотр и экспорт показывает текущий черновик и предупреждения. Для записи файла сначала нужно подтвердить изменения. Внизу страницы показано состояние последнего экспорта; при ошибке подробности доступны в просмотре.

## Копирование и профили

1. Выбери настроенную гирлянду и нажми **Копировать / применить профиль**.
2. Отметь одну или несколько гирлянд-получателей.
3. Выбери сопоставление и политику замены.
4. Нажми **Внести в черновик** и проверь отчёт. Сохрани общий черновик кнопкой **Подтвердить**.

| Режим | Поведение |
|---|---|
| По имени пресета — по умолчанию | Применяет только однозначное совпадение имени в каталоге получателя. Номера у разных гирлянд могут различаться. |
| По номеру пресета | Использует тот же реальный ID. В известном каталоге он должен существовать; при неизвестном каталоге назначение сохраняется с проверкой после подключения. |
| Заполнить только пустые сцены | Оставляет существующие назначения получателя. |
| Заменить совпавшие назначения | Меняет сцены, для которых найден пресет. Не найденные назначения не стираются. |

Отчёт показывает изменения, отсутствующие пресеты, конфликты и назначения, ожидающие каталога. Один пресет нельзя назначить двум сценам одной гирлянды. Автоматической подстановки другого номера при несовпадении нет.

**Сохранить как профиль** создаёт именованный шаблон назначений выбранной гирлянды. В **Профилях** его можно применить сразу к нескольким устройствам или удалить. Создание и удаление профилей также входят в общий черновик. Профиль — шаблон для копирования: после применения назначения гирлянд остаются независимыми.

## Сцены и управление

В YaHA передаётся исходная сущность `light` с типом `light.garland`. Сцена вызывает штатный `select` пресетов того же контроллера. Показаны реальные ID и имена пресетов; порядок кнопок S1…S7 пульта для сопоставления не используется.

| Сцена Алисы | Пример назначения |
|---|---|
| Свеча | `#1 · Тёплое мерцание` |
| Вечеринка | `#7 · Радуга` |
| Ночь | `#12 · Ночник` |

Это пример, а не заводское соответствие. У каждой гирлянды собственная таблица. Список сцен фиксирован возможностями Яндекса; остальные пресеты остаются доступны в WLED и с пульта. Пустая сцена не экспортируется. Без сцен доступны питание, яркость и поддерживаемый данным светом цвет.

Пресет применяется **ко всему WLED-контроллеру**, даже при выборе отдельного сегмента. Прямое управление цветом многосегментного устройства выполняется через цветные сущности сегментов. Имя и комната берутся из реестров HA.

## Экспорт и недоступные устройства

Файл создаётся рядом с `configuration.yaml` по пути `includes/yandex_smart_home_wled.yaml`. При автоматическом подключении добавляется отдельный пакет YaHA; перед изменением существующего YAML сохраняется резервная копия. Существующие включения и настройки других устройств сохраняются. Не принадлежащий интеграции файл не перезаписывается. Код подключения — в `connection.py`.

Автоэкспорт запускается после старта HA, подтверждения настроек, изменения реестров или каталога пресетов; события объединяются с задержкой 3 секунды. Обычная регулировка яркости и переключение пресетов с пульта не вызывают повторную запись файла.

Выбранные гирлянды включаются в экспорт при `unavailable`/`unknown`. Сцены используют известные имена из каталога, сохранённых назначений или предыдущего собственного файла экспорта. Если имя пока неизвестно, экспортируется сам свет; назначение остаётся сохранено и проверяется после появления каталога. **Удалённая/отключённая в реестре HA сущность** отличается от временно недоступной: экспорт сообщает об ошибке и сохраняет предыдущий файл, пока её не уберут из выбора.

Если снять отметки со всех гирлянд и подтвердить, собственный экспорт очищается. Отключение автоэкспорта оставляет сохранение настроек доступным, а запись файла выполняется вручную через **Просмотр и экспорт**.

В интеграции WLED YaHA остаются кнопка **Экспортировать в YaHA** и датчик **Состояние экспорта**. Они не создают отдельное устройство и не требуют назначения пространства. У каждой гирлянды сохраняется её собственное пространство из штатной WLED-интеграции. При обновлении с 0.2.0 служебное устройство «YaHA preset bridge» удаляется автоматически, а entity ID, пользовательские имена и настройки сущностей экспорта сохраняются. Диагностика доступна в меню интеграции. Действие для автоматизаций:

```yaml
action: wled_yaha.export_yaha_config
data:
  dry_run: true
```

При `dry_run: true` выполняется только проверка; при `false` файл записывается и вызывается перечитывание YaHA, если оно доступно. Если HA не может подключить пакет без перезапуска, результат экспорта сообщает об этом.

## Репозиторий и проверки

Архив содержит файлы репозитория сразу в корне. Для обновления репозитория загрузи его содержимое, включая `.github/`. Скрипт `publish.sh` — дополнительный вариант публикации через [GitHub CLI](https://cli.github.com/); сам по себе архив ничего не публикует.

Для HACS в **About → ⚙ → Topics** репозитория нужны подходящие темы, например `wled`, `yaha`, `yandex-smart-home`. Это метаданные GitHub; файлом архива их задать нельзя.

Python-проверки используют Home Assistant 2026.10.4 и реальные реестры/селекторы с тестовыми WLED-данными:

```bash
pip install -r requirements-dev.txt
python -c 'import homeassistant; import unittest; unittest.main(module=None, argv=["unittest", "discover", "-s", "tests", "-v"])'
npm ci --ignore-scripts
npm test
npx playwright install --with-deps chromium
npm run test:browser
```

Нужны Python 3.14 и Node.js 24. GitHub Actions запускает Python, модель черновиков, DOM-проверки, браузерные проверки, HACS и hassfest. Подробности фактически выполненных проверок выпуска — в `VALIDATION.md`.
