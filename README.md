# WLED YaHA

Интеграция Home Assistant для экспорта нескольких гирлянд WLED в «Умный дом с Алисой» через YaHA. Установка и обновления — через HACS, выбор гирлянд и сопоставление сцен — в интерфейсе HA.

Использует штатную интеграцию [WLED](https://www.home-assistant.io/integrations/wled/) для управления устройствами и [YaHA](https://github.com/dext0r/yandex_smart_home) для связи с Яндексом. Подходит для Gledopto GL-MC-001WL с прошивкой WLED. Отдельный MQTT, blueprint и шаблонные светильники не требуются.

## Публикация подготовленного репозитория

Этот исходный архив подготовлен для `Odysseos/ha_wled_yaha`. Репозиторий **не опубликован автоматически**. До публикации ссылки HACS ниже не установят интеграцию.

Распакуй архив, открой терминал в папке `ha_wled_yaha` и выполни:

```bash
./publish.sh
```

Скрипт использует [GitHub CLI](https://cli.github.com/), при необходимости запускает вход через браузер, создаёт публичный репозиторий и отправляет код. Настроенные SSH/HTTPS-предпочтения сохраняются. Он не перезаписывает существующую удалённую историю. Автор коммитов должен быть настроен в Git. Публикация происходит в твоём аккаунте только при запуске скрипта тобой.

Альтернатива без CLI: [создать публичный репозиторий](https://github.com/new) `ha_wled_yaha` и загрузить **содержимое** папки через **Add file → Upload files**. `custom_components/` и `hacs.json` должны находиться в корне репозитория. Не загружай ZIP вместо исходников. Папку `.github/` с проверками при загрузке через браузер можно добавить отдельно.

## Установка через HACS

После публикации открой [добавление WLED YaHA в HACS](https://my.home-assistant.io/redirect/hacs_repository/?owner=Odysseos&repository=ha_wled_yaha&category=integration).

Или: **HACS → ⋮ → Пользовательские репозитории →** `https://github.com/Odysseos/ha_wled_yaha` → тип **Интеграция**. Найди **WLED YaHA**, скачай и перезапусти Home Assistant.

Дальше:

1. Добавь гирлянды через **Настройки → Устройства и службы → Добавить интеграцию → WLED**, если они ещё не добавлены.
2. Открой **Настройки → Устройства и службы → Добавить интеграцию → WLED YaHA**.
3. Выбери сразу все нужные гирлянды. Для обычной гирлянды с одним сегментом выбирай цветной свет, а не необязательную общую сущность.
4. Для каждой гирлянды сопоставь сцены Алисы и реальные пресеты WLED. «—» отключает сцену. Проверь предложенные совпадения по имени.
5. Оставь включёнными **Автоматически обновлять экспорт** и **Автоматически подключить экспорт к YaHA через packages**. Перед сохранением показаны выбранные соответствия и возможные ошибки.
6. В параметрах YaHA выбери **YAML** как источник списка устройств, если там сейчас метки или интерфейс. Наша интеграция эту настройку YaHA не меняет.
7. В приложении **Дом с Алисой** открой подключение YaHA и обнови список устройств.

В `configuration.yaml` не нужна секция `wled_yaha:`. Копировать `custom_components/` и создавать YAML вручную при установке через HACS не нужно.

Если раньше был установлен предварительный YAML-экспортёр, убери его старое подключение `wled_yaha:`/`includes/wled_yaha.yaml`: настройки новой версии хранятся в HA. Старый сгенерированный файл поддерживается и обновляется на месте. Старые соответствия из YAML автоматически не импортируются; выбери их в мастере.

## Как устроено управление

В YaHA передаётся исходный `light` WLED с типом `light.garland`. Питание, яркость и поддерживаемые данным светом цвета работают через штатную WLED-интеграцию. Сцены используют `select` пресетов того же контроллера.

Например, в мастере можно задать:

| Сцена Алисы | Пресет конкретной гирлянды |
|---|---|
| Свеча | `#1 · Тёплое мерцание` |
| Вечеринка | `#7 · Радуга` |
| Ночь | `#12 · Ночник` |

Это пример, а не заводское соответствие. Имена `S1…S7`, номера кнопок пульта и порядок в выпадающем списке не используются для угадывания ID. При отсутствии доступа к каталогу ID мастер может показать имена из штатного `select`; такая привязка хранится по имени.

Одна сцена выбирает один пресет, один пресет назначается одной сцене. У каждой гирлянды своя таблица. Произвольные новые названия сцен Яндекс не поддерживает; поэтому в мастере фиксированный список сцен Алисы. Несопоставленные пресеты остаются доступны в WLED и с пульта.

Пресет применяется **ко всему контроллеру**, даже при выборе отдельного сегмента. Общий свет многосегментного WLED поддерживает питание и общую яркость; прямой выбор цвета доступен на сегментах. Имена и комнаты берутся из реестров HA; назначь устройство нужной комнате в HA.

## Изменение настроек и экспорт

**Настройки → Устройства и службы → WLED YaHA → Настроить**:

- **Гирлянды и сцены** — добавить/удалить гирлянды, изменить сопоставления.
- **Параметры экспорта** — включить/выключить автоэкспорт и автоматическое подключение.
- **Экспортировать сейчас** — проверить и обновить конфигурацию.

На устройстве **WLED YaHA** также есть кнопка **Экспортировать в YaHA** и датчик **Состояние экспорта**. В атрибутах датчика показаны ошибки и предупреждения. Диагностику можно скачать через меню интеграции.

С включённым автоэкспортом обновление выполняется после запуска HA, сохранения настроек, изменений реестров и списка пресетов. Обычное изменение яркости, включение или нажатие пульта экспорт не запускает. События объединяются с задержкой 3 секунды. Если гирлянда недоступна или выбранный пресет исчез, предыдущий файл сохраняется, датчик показывает ошибку. После восстановления связи экспорт повторяется.

При переименовании сущности связь сохраняется по ID реестра HA. При переименовании пресета привязка по номеру сохраняется; привязку по имени при необходимости нужно выбрать заново. После удаления и повторного добавления WLED с новыми сущностями может понадобиться повторный выбор гирлянды.

Для автоматизаций доступно действие:

```yaml
action: wled_yaha.export_yaha_config
data:
  dry_run: true
```

`dry_run: true` возвращает YAML и диагностику без записи файлов. Для записи используй `false` или кнопку экспорта. Реальные соответствия сохраняются в параметрах интеграции, а не в данных действия.

## Автоматическое подключение YaHA

Генерируется отдельный файл `includes/yandex_smart_home_wled.yaml` с `filter.include_entities` и `entity_config`. Он содержит только выбранные гирлянды. К уже существующим пакетам добавляется `wled_yaha_generated`:

```yaml
homeassistant:
  packages:
    wled_yaha_generated:
      yandex_smart_home: !include includes/yandex_smart_home_wled.yaml
```

Настройки других устройств, включая пакет Vakio, сохраняются. Интеграция дописывает отдельный ключ, не пересериализуя существующие YAML, `!include`, `!secret` и комментарии. Перед изменением существующего файла сохраняется точная копия с суффиксом `.wled-yaha.bak`. Поддерживаются обычные словари `packages`, `!include`, `!include_dir_named` и `!include_dir_merge_named`, а также `homeassistant: !include ...`.

При конфликте имени пакета, занятом ручном файле экспорта, повторяющихся нужных ключах, YAML merge в дополняемом словаре, неподдерживаемом формате или пути за пределами каталога HA подключение останавливается с объяснением. Файл, созданный не этой интеграцией, не перезаписывается.

При изменении экспорта вызывается `yandex_smart_home.reload`, если YaHA загружена. Датчик сообщает, если требуется перечитать её вручную. Обновление устройств в приложении Яндекса выполняется пользователем. Если те же светильники уже описаны в другом `entity_config`, перенеси их настройку в WLED YaHA: дублирующиеся записи пакетов могут конфликтовать при объединении HA.

Отключение автоматического подключения не удаляет уже созданное подключение. Удаление интеграции оставляет по этому пути пустой, валидный экспорт и пытается перечитать YaHA; остальные устройства не исключаются. Служебный пакет можно оставить, он больше ничего не добавляет.

## Проверки

Проверено на реальном ядре **Home Assistant 2026.10.4**, Python 3.14.10: 49 тестов, включая реальные реестры HA, схемы форм, мастер настройки, отмену параметров, запись файлов и вызов службы перечитывания YaHA. Сетевые данные WLED и обработчик службы YaHA в этих тестах заменены тестовыми данными. Проверка на физической гирлянде и в аккаунте Яндекса ещё не выполнена.

```bash
python -m pip install -r requirements-dev.txt
python -c 'import homeassistant; import unittest; unittest.main(module=None, argv=["unittest", "discover", "-s", "tests", "-v"])'
```

В репозитории подготовлены проверки тестов, HACS и hassfest через GitHub Actions. До публикации удалённые проверки не запускались.
